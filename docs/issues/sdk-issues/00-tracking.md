# Tracking: SDK fixes needed for FetchXML Studio on Azure Static Web Apps (browser SPA)

FetchXML Studio (a FetchXML query builder for Dataverse, AGPL-3.0) is getting a standalone web
build on Azure Static Web Apps that uses this SDK for all Dataverse access, from the browser and
over CORS, with MSAL tokens. A review of `main` at `f45e6fd` (packages 1.0.0) found the issues
below. Each was reproduced against the built `dist/` packages with a fake `fetchProvider`; the
repro code and output are in each issue.

these bugs sit at boundaries the tests mock (see the test-infrastructure issue).

## What FetchXML Studio uses from the SDK

- `DataverseClient` with `send()` and `api()`, `retry: { maxRetries: 0 }` (the app owns
  throttling), a custom logger, and `fetchProvider`.
- An app-owned MSAL `PublicClientApplication`, through `AccessTokenProvider`, until the
  auth-msal-browser issues are fixed.
- Later: `fetchXml()`, a working `BatchRequestBuilder`, `MetadataClient` reads,
  `DiscoveryClient`, and selected functions and actions.

Until a fix ships, the app works around it behind its own gateway. Each issue lists its
workaround.
