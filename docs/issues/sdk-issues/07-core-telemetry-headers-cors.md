# core: every request carries x-ms-sdk-version / x-ms-correlation-id / x-ms-feature-usage (forcing CORS preflights); the correlation id is per client, not per request; SDK version is hard-coded to 0.1.0
<!-- labels: bug,enhancement,P0,pkg:core,browser,fetchxml-studio -->

## Summary

`TelemetryMiddleware` always adds three custom request headers, even when no telemetry client is
configured:

- `x-ms-sdk-version: dataverse-sdk-js/0.1.0`. The version is hard-coded (`TODO`), but the package
  is 1.0.0.
- `x-ms-correlation-id`. It is set once with `ctx.correlationId ??= uuid()` on the context that the
  whole client shares, so **every request from a client has the same id**.
- `x-ms-feature-usage`.

In a browser SPA each of these is a non-simple header. Every GET then needs a CORS preflight, and
it fails outright if Dataverse's `Access-Control-Allow-Headers` doesn't list them.

`ctx.attempt` lives on the same shared context. Concurrent requests overwrite each other's
attempt, so telemetry reports the wrong `retry.attempt`.

## Why FetchXML Studio needs this

FetchXML Studio on Azure Static Web Apps calls Dataverse cross-origin, straight from the browser.
It needs a header set it can control: ideally only `Authorization`, `Accept`, `OData-*`, `Prefer`
and `If-Match`. It also needs a correlation id per request for support.

## Root cause

- `packages/dataverse-sdk-core/src/middleware/TelemetryMiddleware.ts:11, 26-38`.
- The shared `ctx` is at `packages/dataverse-sdk-core/src/client/DataverseClient.ts:34-37, 73`.

## Proposed fix

- Add `DataverseClientOptions.diagnosticHeaders?: boolean | { sdkVersion?: boolean; correlationId?: boolean; featureUsage?: boolean }`.
  It defaults to `false` in browsers (`typeof window !== "undefined"`) or for everyone. At minimum,
  it must be possible to turn the headers off.
- Create a per-request context (`{ ...this.ctx, correlationId: uuid(), attempt: 0 }`) in
  `DataverseClient.send()`. Put the correlation id on errors (`DataverseError.correlationId` is
  never set today).
- Generate `SDK_VERSION` from `package.json` at build time (tsup `define`).

## Acceptance criteria

- [ ] With `diagnosticHeaders: false` the request carries no `x-ms-*` headers.
- [ ] Two requests get different correlation ids.
- [ ] The version header matches `package.json`.

## Notes

Dataverse's CORS response for SPA origins needs a live check in a browser: which request headers
are allowed, and which response headers (`Retry-After`, `x-ms-dop-hint`, `OData-EntityId`, `ETag`)
are exposed. If `x-ms-dop-hint` isn't exposed, adaptive concurrency silently does nothing in
browsers. That should be documented.
