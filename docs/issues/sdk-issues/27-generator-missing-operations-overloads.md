# generator: ExportToExcel isn't generated, and operation overloads with different bindings overwrite each other (one file per name)
<!-- labels: bug,needs-verification,P2,pkg:actions,pkg:functions,generator,fetchxml-studio -->

## Summary

1. **ExportToExcel isn't generated.** `ExportToExcelAction` doesn't exist in `actions`, `messages`
   or `functions`. FetchXML Studio calls the unbound `ExportToExcel` action (View, FetchXml,
   LayoutXml, QueryApi, QueryParameters) today through the Web API, so the operation exists in real
   orgs. The CSDL snapshot the packages were generated from isn't checked in, so it's unclear
   whether it was missing from the snapshot or filtered out by the generator.
2. **Overloads overwrite each other.** The generator writes one file per operation **name**, so
   CSDL overloads that differ only by binding (for example the same function bound to `systemuser`
   and to `team`) silently overwrite each other. `RetrievePrincipalAccessFunction` comes out bound
   to `organizations(...)`.

## Root cause

- `tools/generate-sdk-types/src/generators/functions-generator.ts:109-115`
- `actions-generator.ts:109-120` (keyed by name)

## Proposed fix

- Check the `$metadata` snapshot into the repo (or its hash and the org version), so generation is
  reproducible and reviewable.
- Generate ExportToExcel.
- Key generated operations by name + binding, for example `RetrievePrincipalAccessSystemUserFunction`
  or an overload union. Log a warning on any collision.
