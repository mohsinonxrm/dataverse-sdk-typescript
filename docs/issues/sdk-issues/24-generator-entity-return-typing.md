# actions, functions (generator): entity-returning operations are typed as { value: T }, but the payload is the entity itself
<!-- labels: bug,P2,pkg:actions,pkg:functions,generator -->

## Summary

For an operation whose return type is a single entity (ExecuteWorkflow returns `asyncoperation`),
the generated response interface declares `value: asyncoperation`. The runtime value is the entity
object (`{ '@odata.context': '$metadata#asyncoperations/$entity', asyncoperationid: … }`). The
correct-looking `res.value.asyncoperationid` is `undefined` at runtime, and the correct
`res.asyncoperationid` doesn't type-check.

## Repro (`repro/gen/02-actions.mjs`)

```
ExecuteWorkflow.parseResponse -> { '@odata.context': '$metadata#asyncoperations/$entity', asyncoperationid: 'aaa' }
```

## Root cause

`tools/generate-sdk-types/src/generators/actions-generator.ts:389-393`, and the same logic in
`functions-generator.ts:456-460`.

## Proposed fix

Emit `value:` only for primitive and collection returns. Type entity and complex returns as the
type itself, with optional `@odata.*` properties.

## Acceptance criteria

- [ ] `(await client.execute(new ExecuteWorkflowAction(…))).asyncoperationid` type-checks and works.
