# core: request builder hides the Response, so create() can't return the new id (OData-EntityId), ETags are unreachable, and get() on 204 throws SyntaxError
<!-- labels: bug,enhancement,P0,pkg:core,fetchxml-studio -->

## Summary

`get()`, `post()`, `patch()`, `put()` and `delete()` return only the parsed body. As a result:

- A create without `return=representation` (204 + `OData-EntityId`) resolves to `undefined`, and
  the new record's id is lost.
- `ETag`, `Preference-Applied`, `x-ms-service-request-id` and `Location` are unreachable.
- `get()` calls `res.json()` unconditionally, so a 204 or empty-body response throws
  `SyntaxError: Unexpected end of JSON input`.

## Why FetchXML Studio needs this

Save view creates `savedquery` and `userquery` records and needs the new id. Support needs the
service request id. `Preference-Applied` tells FetchXML Studio whether formatted values were
actually applied.

## Repro (`repro/core.mjs`, cases 4 and 4b)

```js
// server answers 204 with OData-EntityId: …/accounts(00000000-0000-0000-0000-000000000001)
await c.api('/accounts').post({ name: 'x' });          // → undefined
// server answers 204, no body
await c.api('/accounts(…)/Microsoft.Dynamics.CRM.Foo').get();
```

## Root cause

`packages/dataverse-sdk-core/src/client/DataverseRequestBuilder.ts:240-285`: the methods return
parsed JSON, and `get()` has no empty-body guard.

## Proposed fix

- Add `send<T>(method, body?, options?): Promise<DataverseResponse<T>>` (or
  `getResponse()` / `postResponse()`), returning `{ status, headers, body, entityId?, etag? }`.
- Add a `create(entitySet, record, opts)` convenience that returns the id from `OData-EntityId`, or
  from the body when `return=representation` is set.
- Make `get()` and `delete()` tolerate an empty body (return `undefined`).

## Acceptance criteria

- [ ] The new id is available from a 204 create.
- [ ] `get()` on 204 resolves to `undefined`.
- [ ] Tests cover both cases.
