# xrm: OrganizationService create, retrieve, retrieveMultiple and update throw TypeError against the real builder, and Prefer/If-Match/MSCRMCallerID headers are silently dropped
<!-- labels: bug,P1,pkg:xrm -->

## Summary

`OrganizationService` treats the builder as if it returned a `Response`, and passes header maps
where `RequestOptions` is expected:

- `builder.post(entity, headers)`, `builder.get(headers)`, `builder.patch(entity, headers)` and
  `builder.delete(headers)`: `headers` lands in `RequestOptions`, so `Prefer`, `If-Match`,
  `If-None-Match`, `MSCRMCallerID` and `MSCRM.SuppressDuplicateDetection` are never sent.
- `create()` then reads `response.headers.get("OData-EntityId")` on `undefined` (TypeError).
- With `returnRepresentation`, and in `retrieve()` and `retrieveMultiple()`, it calls
  `response.text()` on a parsed object (TypeError).
- `update()` with `ifMatch` silently does an unconditional update. That is a lost-update hazard.

`whoAmI()`, `delete()` (minus headers), `associate()`, `disassociate()`, `assign()` and
`setState()` work.

## Repro (`repro/xrm.mjs`)

```
## X1. create() against a real 204 + OData-EntityId
THREW TypeError: Cannot read properties of undefined (reading 'headers')
## X1b. create(..., {returnRepresentation:true}) — is Prefer sent?
THREW TypeError: response.text is not a function        (prefer header sent: undefined)
## X2. retrieve()
THREW TypeError: response.text is not a function
## X3. retrieveMultiple()
THREW TypeError: response.text is not a function
## X4. update() with ifMatch — is If-Match sent?
 { headers: { … no if-match … } }
```

## Root cause

`packages/dataverse-sdk-xrm/src/OrganizationService.ts:113, 117, 122, 216-217, 287-291, 334, 453-454, 511, 561`.

`packages/dataverse-sdk-xrm/test/OrganizationService.test.ts` mocks `client.api()` to return
`Response`-like objects, so the suite passes (30/30).

## Proposed fix

- Use `{ headers }` as `RequestOptions`, or the builder's `.prefer()`, `.ifMatch()` and
  `.impersonate()`.
- Use the response-returning builder API (see the response-headers issue) for create and
  `OData-EntityId`.
- Replace the mocks with a fake-`fetch` client.

## Acceptance criteria

- [ ] X1 to X4 send the right headers and return the right values against a fake `fetch`.

FetchXML Studio does not plan to use `xrm` (it will use `client.api()`/`send()`), but the package
is published as a usable facade.
