# core: builder ergonomics and doc mismatches (prefer() breaks chaining, getAll({ maxPages }) ignored, expand() options object documented but not supported)
<!-- labels: bug,documentation,P2,pkg:core -->

## Summary

1. **`prefer()` breaks chaining.** With no arguments, `prefer()` returns a `PreferBuilder`, which
   has no `get` or `post`. The documented one-liner
   `client.api('/accounts').prefer().allAnnotations().get()` therefore fails.
2. **`getAll({ maxPages })` is ignored.** `pages++` runs once, after the loop.
3. **`expand()` takes strings only.** `docs/SDK-USAGE-PATTERNS.md` shows
   `.expand("primarycontactid", { select: [...] })`, which does not type-check.
4. **`docs/v1-api-surface.md` lists exports that don't exist:**
   - `createMsalBrowserProvider`
   - the `MicrosoftDynamicsCRM` namespace
   - `Metadata.*` builders
   - `BatchRequest` / `ChangeSet`
   - `DiscoveryClientOptions` / `Cloud`
   - `createAppInsightsTelemetry` / `createOpenTelemetryTelemetry`

   The middleware order in `docs/SDK-USAGE-PATTERNS.md` also differs from
   `pipeline/DefaultMiddleware.ts`.
5. **Unimplemented options.** `DataverseClientOptions.circuitBreaker`, `bulkhead` and
   `defaultPrefer` are declared but nothing reads them.

## Repro (`repro/core.mjs`, cases 11 and 12)

## Proposed fix

- Give `PreferBuilder` a `done()` / `.and` method that returns the request builder, or make the
  argument-less `prefer()` take a callback: `prefer(p => p.allAnnotations())`.
- Count pages inside the loop.
- Support `expand(nav, { select, filter, orderBy, top })`.
- Implement `defaultPrefer` (useful: `odata.include-annotations="*"` for every GET), or remove the
  unimplemented options.
- Correct the docs.
