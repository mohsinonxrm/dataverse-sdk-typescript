# appinsights, otel: telemetry adapters are stubs whose methods throw "not implemented", so passing one as telemetry makes every request fail
<!-- labels: bug,P1,pkg:appinsights,pkg:otel -->

## Summary

`ApplicationInsightsTelemetryClient` and `OpenTelemetryClient` are published as 1.0.0. Every method
(`trackEvent`, `trackDependency`, `trackException`) throws. `TelemetryMiddleware` calls
`trackDependency` after each response, so configuring either adapter turns **every** Dataverse
request into an exception.

## Repro (`repro/telemetry.mjs`)

```
## T. appinsights: request with telemetry adapter
THREW Error: ApplicationInsightsTelemetryClient.trackDependency not implemented
## T. otel: request with telemetry adapter
THREW Error: OpenTelemetryClient.trackDependency not implemented
```

## Root cause

- `packages/dataverse-sdk-appinsights/src/ApplicationInsightsTelemetryClient.ts:22-49`
- `packages/dataverse-sdk-otel/src/OpenTelemetryClient.ts:31-50`
- `TelemetryMiddleware` doesn't guard telemetry calls, so a failing telemetry sink breaks the
  request (`packages/dataverse-sdk-core/src/middleware/TelemetryMiddleware.ts:44-82`).

## Proposed fix

1. **Core:** wrap telemetry calls in try/catch, so telemetry must never fail a request.
2. **Adapters:** implement them, or deprecate the published 1.0.0 with `npm deprecate` and mark
   them experimental.
3. **Browser adapter:** `@azure/monitor-opentelemetry` is Node-only. A browser app needs one based
   on `@microsoft/applicationinsights-web`. Consider a separate `dataverse-sdk-appinsights-web`
   package or a documented recipe.

## Acceptance criteria

- [ ] A throwing telemetry client doesn't fail requests.
- [ ] The adapters either work or are clearly marked unusable.
