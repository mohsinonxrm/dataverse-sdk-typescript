# auth-msal-browser: no_account isn't treated as interaction required; interactive requests drop account/loginHint; concurrent getToken() calls open several popups; active account isn't set; silently uses accounts[0]
<!-- labels: bug,P0,pkg:auth-msal-browser,browser,fetchxml-studio -->

## Summary

`MsalBrowserTokenProvider.getToken()` has these problems:

1. **The first call fails instead of signing in.** With no account, `acquireTokenSilent` throws
   `BrowserAuthError("no_account_error")`. That is not an `InteractionRequiredAuthError`, so the
   provider rethrows it as `DataverseAuthenticationError`. The README says the first call triggers
   the popup.
2. **Interactive requests drop the account.** Popup and redirect requests carry neither `account`
   nor `loginHint`. After a consent or MFA step-up for a signed-in user, MSAL shows the account
   picker, and the user can pick a *different* account. The new account isn't made active
   (`setActiveAccount`) afterwards.
3. **No single-flight.** N concurrent `getToken()` calls that need interaction start N popups. In a
   real browser, MSAL throws `interaction_in_progress` for the 2nd to Nth, so N-1 requests fail.
   A grid that loads metadata in parallel hits this on the first consent.
4. **Arbitrary account.** With several cached accounts and no active one, it silently uses
   `accounts[0]`, which may belong to another tenant.
5. **The app can't control prompts.** Nothing decides *whether* an interactive prompt may happen.
   A background loop (a "Retrieve All" of 50 pages) can open a popup without a user gesture, which
   browsers block.

## Root cause

`packages/dataverse-sdk-auth-msal-browser/src/MsalBrowserTokenProvider.ts`:

- `:148, :234-243`: account selection, with the `accounts[0]` fallback.
- `:172`: only `InteractionRequiredAuthError` triggers interaction.
- `:195-218`: the popup and redirect requests omit `account` and `loginHint`.
- No `setActiveAccount` after a popup, and no in-flight promise sharing.

## Proposed fix

- Treat `BrowserAuthError` codes `no_account_error`, `no_tokens_found`, `monitor_window_timeout`
  and `interaction_required`, plus `InteractionRequiredAuthError`, as interaction required.
- Pass `account` and `loginHint: account.username` on interactive requests, and
  `setActiveAccount(result.account)` afterwards.
- Single-flight interactive acquisition: concurrent callers await the same promise, keyed by
  scopes.
- Add `onInteractionRequired?: (request) => Promise<"popup" | "redirect" | "fail">`, or
  `interactionType: "none"`, so the app can show a "Sign in to continue" button (a user gesture)
  instead of the SDK opening a popup.
- Make the "no active account" behaviour explicit: throw a typed `NoActiveAccountError` instead of
  using `accounts[0]`, or provide an option to pick.
