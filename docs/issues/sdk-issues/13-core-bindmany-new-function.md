# core: bindMany() loads the batch package with new Function("return import(...)"), which fails in bundlers and browsers and requires CSP 'unsafe-eval'
<!-- labels: bug,P1,pkg:core,browser -->

## Summary

`DataverseRequestBuilder.bindMany()` does
`new Function("return import('@mohsinonxrm/dataverse-sdk-batch')")`:

- Bundlers (Vite, Rollup, webpack, esbuild) can't see the import. In a browser, a bare specifier
  then fails at runtime.
- The `Function` constructor is blocked by any Content-Security-Policy without `'unsafe-eval'`. A
  hosted SPA such as FetchXML Studio on Azure Static Web Apps serves a strict CSP.
- Even in Node it fails unless batch is resolvable from core's own location. With the pnpm
  workspace layout it isn't, because core doesn't depend on batch.

Also, `bindMany()` is `async`. It returns a Promise, not the builder, so the documented chaining
(`.bindMany(...).post()`) is a TypeError.

## Repro (`repro/core2.mjs`, case 15)

```
## 15. bindMany
 rejected: bindMany requires @mohsinonxrm/dataverse-sdk-batch to be installed. Install it with: pnpm add @mohsinonxrm/dataverse-sdk-batch
```

The batch package *is* installed in the workspace.

## Root cause

`packages/dataverse-sdk-core/src/client/DataverseRequestBuilder.ts:195-230` (`new Function` at `:199`).

## Proposed fix

Move `bindMany` into the batch package, for example `associateMany(client, …)`, or take the batch
builder as a parameter. Remove the `Function` constructor from core.

## Acceptance criteria

- [ ] No `new Function` or `eval` in any published bundle; add a CI grep.
- [ ] Associating several records works through the batch package.
