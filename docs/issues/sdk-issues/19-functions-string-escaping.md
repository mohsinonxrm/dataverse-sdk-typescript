# functions (generator): Edm.String parameters are wrapped in '…' without doubling embedded quotes, so any FetchXML with single-quoted attributes produces an invalid literal
<!-- labels: bug,P0,pkg:functions,generator,fetchxml-studio -->

## Summary

The generated functions serialize string parameters as `` `'${x}'` ``. OData string literals must
escape an embedded `'` as `''`, so the literal ends at the first `'` inside the value. FetchXML
commonly uses single-quoted attributes (`<entity name='account'>`). Values such as `O'Brien`
appear in conditions. Affected generated functions include FetchXmlToQueryExpression,
ValidateFetchXmlExpression and every other function with an `Edm.String` parameter.

## Why FetchXML Studio needs this

FetchXML Studio calls `FetchXmlToQueryExpression` (code generation) and `ValidateFetchXmlExpression`
(Query Advisor) on arbitrary user FetchXML.

## Repro (`repro/gen/01-functions-url.mjs`)

```js
new FetchXmlToQueryExpressionFunction(`<fetch><entity name='account'><attribute name='name'/><filter><condition attribute='name' operator='eq' value='O''Brien &amp; Co+1'/></filter></entity></fetch>`).toRequestInformation(base)
```

```
decoded @p1 = '<fetch><entity name='account'><attribute name='name'/>…value='O''Brien &amp; Co+1'/></filter></entity></fetch>'
```

The decoded alias should be `'<fetch><entity name=''account''>…'`.

## Root cause

`tools/generate-sdk-types/src/generators/functions-generator.ts:398` (unbound) and `:351` (bound)
emit ``typeof x === 'string' ? `'${x}'` : String(x)``.

## Proposed fix

Emit a shared runtime helper, for example `odataLiteral.string(v) => "'" + v.replace(/'/g, "''") + "'"`,
and choose the serializer by `paramType` at generation time (see the Guid/DateTimeOffset and enum
issues). Regenerate.

## Acceptance criteria

- [ ] The decoded alias above has doubled quotes.
- [ ] Unit tests cover strings containing `'`, `&`, `+`, `#`, `%`, newlines and non-ASCII.
