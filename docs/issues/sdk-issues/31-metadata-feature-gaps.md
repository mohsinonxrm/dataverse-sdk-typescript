# metadata: support typed attribute casts with $expand, LabelLanguages, an entity-set-name lookup and cache, and escaped key values
<!-- labels: enhancement,P1,pkg:metadata,fetchxml-studio -->

## Summary

A FetchXML builder needs these metadata reads, which `MetadataClient` can't express today:

1. **Typed casts with expand.** For example
   `EntityDefinitions(LogicalName='account')/Attributes/Microsoft.Dynamics.CRM.PicklistAttributeMetadata?$select=LogicalName&$expand=OptionSet($select=Options),GlobalOptionSet($select=Options)`,
   and the String, Money, DateTime, Decimal, Double, Lookup, Status and State casts.
   `getAttributeDefinitions` is typed `Omit<…, "expand">` (`MetadataClient.ts:185`) and has no cast
   option. Raw `client.api(...)` produces the right URL, but any realistic `$select` or `$expand`
   then hits the validateUrl issue.
2. **LabelLanguages / LCID.** There is no `LabelLanguages` option for localized labels.
3. **Entity-set-name lookup and cache.** Every consumer needs `logicalName → EntitySetName`. Naive
   pluralization is wrong for about 10% of custom tables (FetchXML Studio #61). A
   `getEntitySetName()` backed by a cached `EntityDefinitions?$select=LogicalName,EntitySetName`
   would let `xrm` drop its pluralizer too.
4. **Key values aren't escaped.** `getEntityDefinition("x'y")` sends
   `EntityDefinitions(LogicalName='x'y')`. The impact is low for logical names, but it should be
   correct.

The URLs that are correct today (`repro/gen/03-metadata.mjs`):

- `getEntityDefinitions`, `getEntityDefinition`;
- `getAttributeDefinitions` with `IsValidForAdvancedFind/Value eq true`;
- the 1:N, N:1 and N:N relationship reads;
- `getGlobalOptionSet(Name='…')`.

## Proposed API

```ts
getAttributeDefinitions(entity, { cast?: "PicklistAttributeMetadata" | …, select?, filter?, expand?: string | string[], labelLanguages?: number[] })
getEntitySetName(logicalName): Promise<string>          // cached per client
```

## Acceptance criteria

- [ ] The documented typed-cast URL above can be produced through the API, including
      `&LabelLanguages=1033`.
- [ ] `getEntitySetName('account') === 'accounts'` comes from metadata and is cached.
- [ ] Key values are escaped.
