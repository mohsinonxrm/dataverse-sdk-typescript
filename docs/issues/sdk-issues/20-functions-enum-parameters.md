# functions (generator): enum parameters are serialized as numbers or quoted names instead of Microsoft.Dynamics.CRM.Enum'Member', and enum values aren't exported at runtime
<!-- labels: bug,P1,pkg:functions,generator -->

## Summary

OData enum parameters must be sent as qualified enum literals, for example
`@p1=Microsoft.Dynamics.CRM.EntityFilters'Entity,Attributes'` (flags joined by commas). The
generated functions send:

- `RetrieveEntity(1, …)` → `@p1=1`
- `RetrieveEntity('Entity', …)` → `@p1='Entity'`
- `RetrieveAllEntities(1, false)` → `@p1=1`
- `RetrieveMetadataChanges(…)` → `DeletedMetadataFilters=0`

The enums are generated as TypeScript enums but re-exported **type-only**. The package root
doesn't export `./types`, so `'EntityFilters' in functions` is `false` and callers can't reach the
values.

## Repro (`repro/gen/01-functions-url.mjs`)

```
EntityFilters exported at runtime? false
[RetrieveEntity (enum=1, guid)]    decoded @p1 = 1
[RetrieveEntity (enum="Entity")]   decoded @p1 = 'Entity'
[RetrieveAllEntities (enum=1)]     decoded @p1 = 1
```

## Root cause

- `tools/generate-sdk-types/src/generators/functions-generator.ts:381-383, 334-336`: `isEnum` is
  computed but only used to skip the complex branch.
- `complex-types-generator.ts:331, 333`: `export type { … }`.
- `functions-generator.ts:473-495`: the index doesn't export types.

## Proposed fix

- For enum parameters, emit ``Microsoft.Dynamics.CRM.${Enum}'${names(value).join(',')}'``. Map the
  number to member names using the CSDL members, and decompose flags.
- Accept either the enum value or a member-name string.
- Export the enums as values from the package root.

## Acceptance criteria

- [ ] `RetrieveEntityFunction(EntityFilters.Entity | EntityFilters.Attributes, …)` gives decoded
      `@p1 = Microsoft.Dynamics.CRM.EntityFilters'Entity,Attributes'`.
- [ ] `RetrieveMetadataChanges` encodes `DeletedMetadataFilters` the same way.
