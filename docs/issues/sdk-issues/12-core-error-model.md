# core: error model gaps: requestId read from headers Dataverse doesn't send, correlationId never set, two unrelated DataverseError classes, raw DOMException on abort, no typed innererror
<!-- labels: bug,P1,pkg:core,fetchxml-studio -->

## Summary

1. **`requestId` is always `undefined`.** `parseODataError` reads `x-ms-request-id` or `req-id`.
   Dataverse sends `x-ms-service-request-id` and `REQ_ID`, the ids support asks for.
2. **`correlationId` is never populated** on errors, even though the client sends one (see the
   telemetry-headers issue).
3. **Two different `DataverseError` classes.**
   - `src/errors/DataverseError.ts` is the base of `DataverseODataError`, `DataverseThrottleError`,
     `DataverseUrlError` and the rest.
   - `src/errors/NamedErrors.ts:9` declares *another* `DataverseError` (with `statusCode`, `date`,
     `body`, `headers`). It is the base of `DataverseAuthenticationError`,
     `DataverseInvalidRequestError`, `DataverseServiceError` and `DataverseNetworkError`.
   - `err instanceof DataverseError` (the exported one) is therefore false for auth and network
     errors, and the field names differ (`status` vs `statusCode`).
4. **Aborts surface as a raw `DOMException` (`AbortError`)**, and network failures as a raw
   `TypeError`. Neither is an SDK type.
5. **No typed access** to `error.innererror` (message, type, stacktrace) or to the
   `@Microsoft.PowerApps.CDS.*` details. They are only reachable through `raw`.

## Why FetchXML Studio needs this

FetchXML Studio maps Dataverse error codes to guidance (`dataverseErrors.ts`) and shows "Copy
details" for support. It needs a stable `{ status, code, message, retryAfterMs, requestId,
correlationId }` on every failure, whatever its cause.

## Root cause

- `packages/dataverse-sdk-core/src/errors/parseODataError.ts:6`
- `packages/dataverse-sdk-core/src/errors/NamedErrors.ts:9`
- `packages/dataverse-sdk-core/src/pipeline/FetchRequestAdapter.ts:27-30`, where there is no
  wrapping.

## Proposed fix

- Read `x-ms-service-request-id` and then `REQ_ID` (keep the old names as fallbacks).
- Set `correlationId` from the request context.
- Make the `NamedErrors` classes extend the single exported `DataverseError`. Keep `statusCode` as
  a deprecated alias of `status`.
- Add `DataverseAbortError` and use `DataverseNetworkError` in the adapter.
- Add `innerError?: { message?: string; type?: string; stacktrace?: string }`.
