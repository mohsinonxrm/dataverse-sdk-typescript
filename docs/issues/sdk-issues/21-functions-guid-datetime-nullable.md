# functions (generator): Edm.Guid and Edm.DateTimeOffset parameters are quoted, and optional (Nullable) parameters can't be omitted
<!-- labels: bug,P1,pkg:functions,generator -->

## Summary

OData `Guid` and `DateTimeOffset` literals are unquoted. The generated functions quote them:

- `RetrieveEntity` MetadataId: `@p3='00000000-0000-0000-0000-000000000000'`
- `LocalTimeFromUtcTime` UtcTime: `@p2='2026-01-01T00:00:00Z'`
- `RetrieveMetadataChanges` AppModuleId: quoted

All parameters are required positional arguments, even when the CSDL marks them `Nullable`.
`RetrieveEntityFunction` therefore always sends a MetadataId. Combined with the enum issue, it
cannot produce a valid request.

Correct today:

- booleans: `false`
- numbers: `85`
- string collections: `["account","contact"]` for RetrieveTotalRecordCount
- `null`: `null`

## Repro (`repro/gen/01-functions-url.mjs`)

```
[RetrieveEntity]         decoded @p3 = '00000000-0000-0000-0000-000000000000'
[LocalTimeFromUtcTime]   decoded @p2 = '2026-01-01T00:00:00Z'
```

## Root cause

- `tools/generate-sdk-types/src/writers/typescript-writer.ts:30-33` maps `Edm.Guid` and
  `Edm.DateTimeOffset` to `string`.
- The runtime template then quotes every string (`functions-generator.ts:398`, `:351`).

## Proposed fix

- Branch on `paramType` at generation time:
  - `Edm.String`: escaped and quoted.
  - `Edm.Guid` and `Edm.DateTimeOffset` (accept `Date`): raw.
  - `Edm.Boolean` and numeric types: `String()`.
- Make `Nullable` parameters optional: an options object, or trailing optional arguments. Omit
  them from the parameter list when they are `undefined`.

## Acceptance criteria

- [ ] Decoded `@p3=00000000-0000-0000-0000-000000000000` and `@p2=2026-01-01T00:00:00Z`.
- [ ] `new RetrieveEntityFunction({ EntityFilters, LogicalName: 'account' })` omits MetadataId.
