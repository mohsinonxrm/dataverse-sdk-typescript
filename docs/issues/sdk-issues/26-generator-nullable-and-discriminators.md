# generator: CSDL Nullable default is inverted (all complex-type properties become required), and abstract parameter types (QueryBase) get no @odata.type discriminator
<!-- labels: bug,P1,pkg:actions,pkg:functions,generator -->

## Summary

1. **Nullable is inverted.** In CSDL a property without `Nullable` is nullable (the default is
   true). The generator makes a property optional only when `Nullable="true"` is explicit. As a
   result `QueryExpression`, `ColumnSet`, `PagingInfo` and others make *every* property required
   (`Distinct`, `NoLock`, `SubQueryExpression`, `PageInfo`, …), so realistic objects need casts.
2. **No `@odata.type` discriminator.** Parameters declared with an abstract or base type need
   `@odata.type` to select the derived type. Examples: `QueryExpressionToFetchXml(Query: QueryBase)`
   and the `BulkDelete` QuerySet. `QueryBase` is generated as an empty interface, and nothing
   requires or allows `@odata.type`.

The generated request bodies (`repro/gen/02-actions.mjs`):

```
[QueryExpressionToFetchXml] body={"Query":{"EntityName":"account","ColumnSet":{"AllColumns":true}}}   ← no @odata.type
```

Whether Dataverse rejects a `QueryBase` without `@odata.type` needs a live check. Microsoft's
samples always send it.

## Root cause

- `tools/generate-sdk-types/src/parsers/edmx-parser.ts:248, 276` keep `@_Nullable` as is.
- `complex-types-generator.ts:160, 217` use `prop.nullable ? "?" : ""`.
- No discriminator is generated for abstract or base types.

## Proposed fix

- Treat `nullable !== false` as optional.
- For a parameter whose type is abstract or has derived types, emit a union of the derived types,
  each with a required `'@odata.type'` literal.
