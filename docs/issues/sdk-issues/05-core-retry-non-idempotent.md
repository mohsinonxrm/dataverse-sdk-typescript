# core: RetryMiddleware resends POST/PATCH/DELETE after 502/503/504, so actions such as ExecuteWorkflow, Close*, BulkDelete and create can run twice
<!-- labels: bug,P0,pkg:core,fetchxml-studio -->

## Summary

`RetryMiddleware` retries every method on `429, 502, 503, 504`.

- A **429** from Dataverse service protection means the request was not executed, so resending is
  safe.
- A **502, 503 or 504** says nothing about whether the server already ran the request: the gateway
  can time out after Dataverse committed. Resending a non-idempotent request, such as a create, an
  action like ExecuteWorkflow, CloseIncident, WinOpportunity or BulkDelete, or a `$batch`, can
  duplicate side effects.

## Why FetchXML Studio needs this

FetchXML Studio runs workflows, close messages and creates on user-selected records, and goes to
some length never to run them twice (#264 in FetchXML Studio). A silent SDK-level resend breaks
that guarantee.

## Root cause

`packages/dataverse-sdk-core/src/middleware/RetryMiddleware.ts:56-62, 88-92`: the method isn't
considered.

## Proposed fix

- By default, retry `GET`/`HEAD`/`OPTIONS` (and `PUT`/`DELETE` if you consider them idempotent) on
  429/502/503/504.
- Retry `POST`/`PATCH` **only on 429**, plus 503 when the response carries `Retry-After` and a
  Dataverse service-protection error code (`0x80072321`, `0x80072322`, `0x80072326`).
- Expose `retryNonIdempotent?: boolean` and `shouldRetry(response, request)` for callers who know
  better.
