`dataverse-gen` can generate form context types per form layout (#430): `"formLayouts": true` reads each table's active main and quick create forms (`systemform` FormXml) and writes `forms/<Entity>Forms.ts` with, per form, `<Entity><Kind>_<Form>Attributes`, `…Controls`, `…Tabs` and `…FormContext`. `getAttribute()` and `getControl()` take the names on that form, including duplicate controls (`name1`), `header_` controls, subgrids (`GridControl`), web resources and IFRAMEs (`IframeControl`), quick view forms (`QuickFormControl`) and the timeline, and return their `@types/xrm` types without `| null`; party list columns are typed as lookups, file and image columns as plain attributes. `ui.tabs.get()` takes the form's tab names and a tab's `sections.get()` its section names. The option turns `formContext` on too. `dataverse-gen validate` checks it; with incremental generation a changed form regenerates its table's files. New exports: `MetadataService.getSystemForms()`, `SystemFormRecord`, `FormLayoutType`, `FormLayoutKind`, `FormTabType`, `FormSectionType`, `FormControlType`, `FormControlKind`, and `EntityType.Forms`; a new `form-layouts.ejs` template (`dataverse-gen eject` copies it).
